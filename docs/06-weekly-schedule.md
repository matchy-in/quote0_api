# Weekly Schedule & Canvas API

Stores a Monday-Sunday schedule in DynamoDB and posts a day's schedule (date + two-column table) to two Quote/0 devices through the [Canvas API](https://dot.mindreset.tech/docs/service/open/canvas_api).

## Components

| File | Responsibility |
|------|----------------|
| `src/lambda/handlers.js` | `saveSchedule`, `getSchedule`, `publishSchedule` handlers (Bearer auth via `API_AUTH_TOKEN`) |
| `src/services/scheduleDbService.js` | DynamoDB access to the `schedule` table |
| `src/services/quote0CanvasService.js` | Builds the Canvas payload and posts it to each device (retries, per-device results) |

## Devices

| Variable | Device | Endpoint |
|----------|--------|----------|
| `QUOTE0_CANVAS_1_API` | Device 1 (`48F6EE55503C`) - schedule | `https://dot.mindreset.tech/api/authV2/open/device/48F6EE55503C/canvas` |
| `QUOTE0_CANVAS_2_API` | Device 2 (`48F6EE543F1C`) - dashboard | `https://dot.mindreset.tech/api/authV2/open/device/48F6EE543F1C/canvas` |

Both use `Authorization: Bearer <QUOTE0_AUTH_TOKEN>` (the Dot. app API key, `dot_app_...`). Defaults for both URLs are set in `serverless.yml`.

## DynamoDB table

`quote0-api-<stage>-schedule` - primary key `day` (`monday` ... `sunday`). Item: `{ day, items: [{ time, task }], updated_at }`. No TTL.

## Endpoints

All require `Authorization: Bearer <API_AUTH_TOKEN>` when `API_AUTH_TOKEN` is set.

### POST /api/schedule

Body: any of `monday` to `sunday`, each a list of `{ "time": "HHMM-HHMM", "task": "..." }`. Days omitted are unchanged; `[]` clears a day.

Validation: `time` matches `^\d{4}-\d{4}$`, `task` at most 60 characters, at most 20 items per day. Errors return `422` with an `errors` array; no days provided returns `400`.

```json
{
  "monday": [
    { "time": "1500-1530", "task": "tidy up lunch bag" },
    { "time": "1530-1600", "task": "TV + Snack" },
    { "time": "1600-1730", "task": "Playtime" },
    { "time": "1730-1800", "task": "Piano practice" }
  ]
}
```

Response `201`: `{ "message": "Schedule saved", "days": ["monday"] }`

### GET /api/schedule

- `GET /api/schedule` -> `{ "schedule": { "monday": [...], ..., "sunday": [...] } }`
- `GET /api/schedule?day=monday` -> `{ "day": "monday", "items": [...] }` (`400` for an invalid day)

### POST /api/schedule/publish

Body (all optional):

| Field | Default | Notes |
|-------|---------|-------|
| `date` | today (Europe/London) | `YYYY-MM-DD` or `YYYY/MM/DD` |
| `day` | weekday of `date` | override to publish another day's schedule |
| `devices` | `SCHEDULE_DEVICE` (`48F6EE55503C`) | array of device serial numbers, e.g. `["48F6EE55503C"]`; the serials come from `QUOTE0_CANVAS_1_API` / `QUOTE0_CANVAS_2_API`. `1` and `2` still work as shortcuts. Device `48F6EE543F1C` shows the dashboard, so publishing there replaces it. |
| `time` | now (Europe/London) | `HHMM` or `HH:MM`, overrides "now" for testing |

Responses:

- `200` - all devices accepted the post
- `502` - at least one device failed (see `results`)
- `404` - no schedule saved for that day
- `400` - invalid `date`, `day` or `devices`

```json
{
  "date": "2026-11-20",
  "day": "friday",
  "items": [{ "time": "1500-1530", "task": "tidy up lunch bag" }],
  "results": {
    "48F6EE55503C": { "success": true, "status": 200, "response": { "message": "..." } },
    "48F6EE543F1C": { "success": false, "status": 404, "error": "..." }
  }
}
```

## Rows shown

Only 4 rows fit on the screen. Publish shows the current item (first one whose end time is later than now) and the next three. If fewer than 4 remain, earlier items fill the screen; after the last item the final 4 are shown. A `date` other than today starts from the first item. The response includes 
ow`, `shown` (what was sent) and `items` (the full day).

## Canvas payload

The screen has 5 rows: a title row (date and time on the left, full weekday name such as `Sunday` at the far right) followed by 4 time | task rows. Rows are generated by the Lambda with the text embedded literally (Mindreset rejected the `get` helper for the row cells, so no template helpers or `$for` are used). `{` and `}` are stripped from text. Font size and row height are the `FONT_SIZE`, `ROW_HEIGHT` and `TIME_COL_WIDTH` constants in `quote0CanvasService.js`.

```json
{
  "refreshNow": true,
  "taskAlias": "Daily schedule",
  "data": { "date": "2026-11-20 Fri" },
  "windowData": { "default": [ { "type": "div", "props": { "...": "see quote0CanvasService.js" } } ] }
}
```

Notes:

- Posts go to the device's **loop** list. Fixed-list items need `taskType: "fixed"` and a `taskKey`, and are not refreshed early by `refreshNow` (not implemented).
- Each device accepts one immediate refresh every 2 seconds; a `429` is retried using `Retry-After`. Up to 3 attempts for network errors, 5xx and 429.
- Publishing is manual; there is no timer yet.

Which device shows what is set by two serial-number variables (defaults in `serverless.yml`): `SCHEDULE_DEVICE` = `48F6EE55503C` (weekly schedule) and `DASHBOARD_DEVICE` = `48F6EE543F1C` (dashboard from the EventBridge job and event creation).
